# Staging deploy (L-8)

Staging runs the API on Render and the database on Supabase. Every push to `main` redeploys the API. Config: [render.yaml](../render.yaml).

| Part | Where | Notes |
|---|---|---|
| API | Render web service `ats-api` (Docker, free plan) | Built from `api/Dockerfile`. Runs `alembic upgrade head`, then uvicorn |
| Redis | Render Key Value `ats-redis` (free plan) | Internal connections only |
| Postgres + pgvector | Supabase (free plan) | Migration 001 runs `CREATE EXTENSION IF NOT EXISTS vector` |

No secrets are in the repo. Secret values are entered in the Render dashboard. `SECRET_KEY` is generated by Render.

## One-time setup

1. **Supabase.** Create a project. In *Connect*, copy the **Session pooler** connection string (port 5432). The direct connection is IPv6-only on the free plan, and Render needs IPv4. Use the `postgresql://` form, not `postgresql+psycopg://`.
2. **pgvector.** Open *Database > Extensions* and check that `vector` is available. The migration enables it, so there is nothing to switch on by hand if your role may create extensions.
3. **Render.** *New > Blueprint*, pick this repo and branch `main`. Render reads `render.yaml` and asks for the two `sync: false` values:
   - `DATABASE_URL`: the Supabase string from step 1.
   - `CORS_ORIGINS`: a JSON list of the web app's origins. Use `[]` until the web app is deployed.
4. Wait for the first deploy, then open `https://ats-api-v9r9.onrender.com/health`. It must return `{"status": "healthy", ...}` with `"environment": "staging"`.

## Free-tier limits to know about

Taken from third-party summaries, not the vendors' pricing pages. Check the current numbers before relying on them.

- **Supabase** pauses a free project after about a week without activity. A paused database makes the API fail at start-up (the migration cannot connect) until someone restores it in the dashboard. Free storage is about 500 MB.
- **Render** free web services sleep after a period without traffic, so the first request after a pause is slow.
- **Uploaded CVs are lost on every deploy.** The API stores files on the instance's local disk (`STORAGE_LOCAL_DIR`), and a free Render instance has no persistent disk. Fine for a smoke test, not for real data.
- The CV extraction worker (Arq) is not deployed, and the image has no Tesseract, so uploads are not processed on staging yet.

## Checking that no secrets are committed

`git grep -n -i -E "postgresql(\+psycopg)?://[^ :]+:[^ @]+@(db|aws|[a-z0-9.-]*supabase)" ` and a look at `git diff main` before merging. `.env` is git-ignored.
